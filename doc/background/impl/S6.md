# S6: authority in T0 (2026-10-28)

Enforces RFC 0001 (forks and authority) dynamically in the T0 reference
interpreter. New namespace `klara.authority` (the store, the split rules,
settlement); machine glue in `klara.eval`; surface names as built-in macros
in `klara.expand`; a new ambient namespace `auth` in `klara.core`. No
Clojure Java sources were consulted.

```
clojure -X:test        # 63 tests, 3959 assertions, 0 failures
```

## 1. What was built

| Piece | Where | What it does |
|---|---|---|
| authority values | `klara.authority/Auth` | an id and a kind; plain, aliasable data (prints `#<evidence>`) |
| the store | `*store*`, `new-store` | one state per authority: `:status` (open, advancing, settled, incomplete), `:operation`, `:scope` (owning branch context), `:owner`, `:gen`, `:payload`; a REPL session has its own store |
| kinds | `op!` | `resource`/`capability` (`consume!`, `use!`), `evidence` (`spend!`, `remaining`, `split`, `join`), `budget` (hard and traded components), `rand-key` (`draw!`), `branch!` (`system`, `merge!`, `discard!`, `advance!`, `partition!`); `transfer!` and `status` for all |
| branch contexts | `{:tag :branch :ctx c}` frames | the chain of contexts is read from the continuation (including machines suspended behind host frames, `*outer-k*`) |
| `fork` | `:auth/fork`, frames `:fork-run`, `:branch`, `:fork-scope` | `(fork opts? [b e ..] body..)`; options `:coupled`, `:transfer {r i}`, `:shares {t [w ..]}`; `adopt!` one branch in the body; scope exit settles the group |
| fork-resume | `Cont` has a `shots` counter | the second resumption is checked (`resume-blocker`) and runs under a `:shot` context |
| deferred intents | `reference-call` in `klara.eval` | an irreversible host call in a fork branch becomes an `Intent`; run on adoption (or handed to the enclosing branch), dropped on discard |
| capability | `(direct cap body..)`, frame `:direct` | irreversible calls run at once and leave a receipt; `cap` is a resource, so only one branch can hold it |
| settlement | `run-op!`, `claim!`, `merge-handle!` | spindel's protocol: claim (open → advancing, preflight), mutate, complete; preflight failure reopens, mutation failure leaves `:incomplete`; repeat of a completed merge/discard returns its result |
| world merge | `merge-roots` | three-way merge of world roots by definition; a symbol changed on both sides is a conflict |

### How a use is checked

A token belongs to the context it was minted in. When code under a chain of
contexts uses token `t`, `resolve-id` walks the chain: if the innermost
context owns `t`, use it; otherwise ask the context's substitution; otherwise
resolve `t` in the outer chain and **derive** a child for this context by the
kind's split rule, leasing the parent (`:advancing`). Every alias of `t`,
however it was reached (another local, a nested collection, metadata, a
closure, a world lookup after capture), meets the same substitution at its
use. This is the Codex review's alternative in §1: references are aliased
freely, and only the authority's use is linear, enforced by the store's
generation-counted state rather than by tracking copies.

At scope exit (`close-group!`) children are settled and parents reopened.
Evidence: the adopted branch's spending is committed, discarded branches'
spending is refunded, and tokens minted in a discarded branch are unminted.
Budget: all spending is charged. Randomness: the parent's key was already
moved to `split(k, n)` when the children were derived. Resource: consumed in
the branch means consumed, otherwise it returns. Branchable: the adopted
child is merged into its parent's branch, the others are discarded. Tokens
minted in the adopted branch move to the parent's scope; those of discarded
branches are settled `:discard`.

## 2. Decisions left open by the RFC, and what was chosen

1. **Where the store lives.** A dynamic var, defaulting to a process-wide
   store; the REPL binds one per session (so transcripts are reproducible).
   A Klara closure called by host code on another thread without the binding
   sees the global store and does not find the session's authorities (an
   error, not a silent duplication). The RFC says "machine/world"; putting it
   in the world root would make authority state part of definitions, which
   it is not.
2. **Lazy or eager split.** Lazy: a branch derives its child at its first use
   of an authority, but then derives all n children at once so shares are
   correct. A fork therefore costs nothing for authorities it does not touch,
   and an unrelated stream's key does not move. Exception: `:transfer` leases
   the resource at fork entry, because a transfer is an explicit move.
3. **Fork-resume split rules.** Randomness is split per resumption; a budget
   is lent whole to the shot (shots run one after another in T0) and charged
   afterwards; branchable children are discarded at the end of the shot.
   Resource **and evidence** are refused: an evidence split needs the number
   of children, which a continuation cannot know. Handlers split evidence
   explicitly (join, then split), as SMC does. RFC 0001 calls evidence
   splittable; this narrows it to explicit splits under multi-shot.
4. **Detection at resumption and at use.** The second resumption walks the
   continuation's frames (locals, collections and their metadata, closure
   captures, partial applications, nested continuations, branch values) and
   refuses captured resource or evidence authorities and open forks.
   Authorities it cannot see (inside lazy sequences, atoms, the world) are
   checked by the shot context when they are used. Both are detected errors;
   the walk only gives the early, clearer message.
5. **Shared contexts are safe.** A continuation captured inside a shot and
   resumed twice shares that shot's context. That is fine because every use
   goes through the store: two continuations may share an authority's
   context, but not its use.
6. **Shots do not defer intents.** Only `fork` branches defer irreversible
   effects. A host effect in a fork-resumed continuation runs each time it is
   reached. This is RFC 0002's replay question (EF6), left open: deferring
   would make enumeration handlers silently drop output, and there is no
   adoption point for a shot.
7. **Exactly once.** As in spindel, repeating a completed `merge!`/`discard!`
   returns the recorded result; every other consuming operation (`consume!`,
   `split`, `join`, `transfer!`, `partition!`) fails on a settled authority.
8. **At most one adopted branch per fork.** Partitioned settlement of disjoint
   systems across branches goes through `partition!`, not through adopting
   several branches.
9. **Cancellation.** An exception unwinding through a `:branch` or
   `:fork-scope` frame discards the group before it propagates (the unwind
   search in `do-perform` stops at those frames, settles, and continues).
   A **user** effect whose clause aborts past a fork without resuming cannot
   be detected (the continuation might be resumed later). The fork's parents
   then stay `:advancing`, so they fail closed and need recovery that does
   not exist yet.
10. **Irreversible classification.** A fixed set of clojure.core functions
    (`println print prn pr printf newline flush spit reset! swap! reset-vals!
    swap-vals! vreset! deliver send send-off`), plus vars with
    `:klara/irreversible` metadata and `classify-irreversible!`. Only
    `:host/call` reaching the reference handler is checked, so a user dynamic
    handler that mocks a host call is unaffected.
11. **Authority operations are not virtualizable.** `:auth/*` operations are
    ambient but never handled by user handlers: a handler could only deny
    service, not forge a transition, and allowing it would complicate the
    check.
12. **Branchable systems are Klara worlds.** `merge!` is a three-way merge
    by definition (fast-forward when the parent did not move). The
    `:advancing` lease covers `advance!` (rebase the branch over the parent).
    `*mutation-hook*` lets tests inject failures between system mutations.
13. **Concurrency.** Single-authority transitions (claim, consume, draw,
    spend, split, join) are one `swap!` on the store, so host threads racing
    on one authority are linearized (tested: one of 16 `consume!` succeeds,
    64 of 100 `spend! 1/64` on mass 1). Fork derivation and group closing are
    multi-step and assume the single-threaded machine that runs the fork.

## 3. What remains design

- **AU7, the static affine layer.** Nothing static exists; every check is
  dynamic.
- **Authorities in the formal semantics** (`spec/`, `doc/semantics.md`):
  the kernel-checked semantics has no store, no fork form, no shot contexts.
  The `auth` ambient namespace is new in `klara.core` and must be added to
  the spec's ambient set when S5 and S6 meet.
- **`fork-following`**: an overlay over the live parent with
  last-writer-wins on conflicting writes.
- **Recovery** from `:incomplete` (spindel: explicit recovery by the owner)
  and from forks abandoned by a non-resuming user effect.
- **Receipts for review.** The log records intents, direct actions and their
  capability, but it is not attached to `adopt!` as a portable adoption
  record (Simmis review, RFC 0001 item 5).
- **Compensation (sagas)** for effects that can be neither deferred nor
  undone (RFC 0001 open question 2), and classification beyond a fixed list
  (`:host/static`, Java methods).
- **Wrapping host state.** Atoms used through host calls other than the
  irreversible list (e.g. `deref`) are still shared by all forks, as at L0.
  RFC 0001's L1 ("hosted atoms become branchable cells") is not done.
- **`within`** and statistical receipts (the guide's city sketch).
- **Cost.** Each authority operation walks the continuation for its context
  chain (linear in depth), and each second resumption walks the captured
  frames. On example 7's 1000-particle SMC run, which resumes many
  continuations more than once and uses no authorities, the run takes about
  550 ms against about 500 ms before S6 (noisy, two runs each). Authority-heavy
  code was not measured.
