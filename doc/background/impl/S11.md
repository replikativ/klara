# S11: licensed numeric representations

## Profiling before changes

Clean room: only Klara source and public Clojure/JVM APIs were used.
`experiments/compiler/profile.clj` measures nine batches of 10,000 calls
after 10,000 warmups with the public ThreadMXBean allocated-byte counter.
Raw results: `experiments/compiler/s11-profile-before.txt`. The existing
short-warmup benchmark is also retained as `s11-bench-before.txt`.

The S9 3.17× numeric ratio is an end-to-end, short-warmup observation,
not a measurement of boxing alone. The emitted loop is a `letfn` with
Object parameters; Clojure's independent baseline infers a primitive
accumulator from its literal initializer. Before JVM optimization this
creates a representation disadvantage. With sufficient warmup HotSpot
eliminates most numeric allocation even in the old emitted code.

At input 200 the old emitted body measured 149 ns / 96 bytes per call,
the read-recording wrapper 121 ns / 80 bytes, cache entry alone 618 ns /
512 bytes, and the full compiled call 2,052 ns / 4,408 bytes. These are
separately warmed samples, not additive costs; inlining and compilation
change between samples. Input 2000 measured body 867 ns / 96 bytes and
full call 2,505 ns / 4,424 bytes. The plain baseline itself changed from
984 ns / 1,752 bytes at 200 to 711 ns / 24 bytes at 2000 as JIT compilation
progressed. These order effects prohibit assigning precise percentages
of the historical gap to individual causes.

The body has no world/Var lookup per iteration: primitive forms call
public Clojure arithmetic, and world functions are guarded/inlined.
Basis validity is memoized once per root; runtime guards, cache lookup,
T0 machine construction, dynamic bindings and `apply` still cost per call.
Both old entry wrappers use `& args`; the emitted one counts/destructures
the argument seq, and the outer one applies again. Wrong arity must still
decline before effects. There are zero generated checkpoints in the four
original benchmark loops, so checkpoint overhead explains none of their
historical gap. The allocation measurements identify the fixed boundary
cost as the dominant warmed numeric cost at input 200.

## Changes and licensing

- Fixed-arity emitted IFns replace both variadic wrappers. An explicit
  `[:arity n]` entry guard preserves T0's wrong-arity errors before effects.
  Inlined read recording is emitted directly into that entry, so derived
  definitions continue recording their world dependencies.
- `compile.unbox` is a deliberately small abstract interpreter over the
  final scalar IR. A directly entered, closed self-tail loop can use Long
  or Double layout only when a runtime class check holds for every initial
  value and every backedge preserves the chosen class. Literal facts prune
  impossible layouts. Explicit `long`/`double` initializer coercions let
  the public Clojure compiler infer primitive locals and backedges.
- Allowed arithmetic is checked `+`, `-`, `*`, `inc`, `dec`; comparisons,
  lets and branches propagate facts. There is no unchecked arithmetic,
  reassociation, division-to-double conversion or replacement of Clojure
  equality/hashing. Overflow exits with the same ArithmeticException.
  `/`, promotion, captures and unknown operations do not prove invariant
  loop layout. They retain ordinary boxed emission.
- Source-aligned numeric loops in a top-level let spine get a checkpoint
  at the loop body entrance. The frame contains the original outer locals,
  a `[:letrec path 0]` descriptor, and current boxed loop arguments. The
  ordinary path checks Long each iteration; a changed type deopts to T0
  there. Three failures poison this check. In an invariant primitive loop,
  the initial class guard and backedge facts subsume that check entirely;
  no feedback lookup or frame construction occurs per iteration.
- Compiler certificate version is `s11-1`. Frame states remain bound by
  the existing digest and install-time shape checks. No T0, authority,
  expansion or affine files changed; deleting the cache still restores T0.

Differential tests inspect numeric result classes, Double raw bits, values,
hashes, equality, map lookup, and exception classes/messages. Inputs include
Long extrema, Double, Ratio, BigInt, NaN, infinity, signed zero and invalid
types. A Counted probe records five iterations while the accumulator changes
to a Ratio/Double after iteration three: exactly one deopt, five observations,
and the same result before installation and after clearing the cache.
Existing generated, authority, exception-resumption and redefinition tests
remain in the suite. Tests are finite evidence, not a proof.

## Decisions and remaining scope

This optimizes a guarded representation region rather than specializing
the entire function on every argument. Mixed representations, general
unboxed layouts, captured loop facts, range analysis, OSR, arbitrary
mid-iteration checkpoints and virtual maps/sets remain open. Loops with
lexical handlers or authority operations retain their previous path;
their frames are not reconstructed by this extension. The existing S9
addition checkpoint remains supported.

The current primitive table does not include `+'`; S11 does not add it or
silently give `+` promotion semantics. Division remains generic and can
produce Ratios. Extending numeric primitives must separately license any
representation that can promote.

The dominant warmed fixed cost is still T0 machine/context construction
and dynamic cache entry. Eliminating it requires a separate direct-call ABI
that preserves basis, continuation and exception-handler context; this
change leaves that boundary intact. No unsupported fast entry that skips
T0's context is presented as an end-to-end improvement.

## Measurements after changes

OpenJDK 25.0.1, Clojure 1.12.4, `-Xmx512m`. The original benchmark is
unchanged: input 200, 100 warmups, median of seven batches of twenty calls,
five compilations; T0/compiled/plain results must agree before timing.
Tests and benchmarks were run sequentially. Raw output is in
`experiments/compiler/s11-results.txt`.

| Function | T0 ms | Compiled ms | Plain ms | Compiled/plain | Compile ms |
|---|---:|---:|---:|---:|---:|
| Numeric | 0.58074 | 0.006524 | 0.004918 | 1.327× | 2.911 |
| Collections | 1.80821 | 0.007650 | 0.020330 | 0.376× | 12.851 |
| Closures | 1.98276 | 0.015511 | 0.013793 | 1.125× | 5.337 |
| Tail effects | 1.16288 | 0.011964 | 0.007014 | 1.706× | 1.981 |

The same-session old compiler measured compiled/plain ratios of 1.851×,
0.703×, 1.687× and 1.392× respectively. Compiled absolute times changed
7.901 → 6.524 µs numeric, 13.608 → 7.650 µs collections, 15.978 → 15.511 µs
closures, and 10.794 → 11.964 µs tail effects. The tail sample is about
11% slower; absence of regression is **not established**. That loop's
emission is unchanged apart from the entry ABI and arity guard. Baseline
times also vary substantially, so attribution needs isolated longer runs.

The ≤1.2× numeric target is **not met end to end**. The original S9
3.17× becomes 1.33× in this sample, but historical ratios are not controlled
before/after evidence. No stable throughput guarantee follows from these
short measurements on a shared machine.

Long-warmup allocation measurements (`s11-profile-after.txt`, same command
as before) at input 200 give plain 106 ns / 24 bytes, emitted numeric body
99 ns / 24 bytes, entry validation 280 ns / 528 bytes, full compiled call
1,536 ns / 4,432 bytes. At input 2000: plain 847 ns, emitted body 784 ns,
full call 2,027 ns / 4,432 bytes. Thus the body reaches roughly parity;
the warmed end-to-end ratio at input 200 is still **14.5×**. The much
larger ratio reflects the improved JIT-warmed plain baseline, not a new
regression relative to the short-warmup measurement.

Before/after body allocation at input 200 is 96 → 24 bytes, and full-call
allocation is 4,408 → 4,432 bytes: eliminating wrapper/loop boxing does
not eliminate entry allocation, and the additional arity guard also costs.
The profiler's `:wrapper` label now calls the same function as `:emitted`;
there is no separate wrapper. All measurements include profiler-loop
overhead; ~0.006 bytes/call is measurement bookkeeping. Sampling order,
JIT phase changes, GC and external load are uncontrolled, with no confidence
intervals. Allocation evidence is stronger than nanosecond comparisons.
