# S7: per-root validity, frame states and deopt (2026-10-28)

Implements the parts of the first compiling tier that do not depend on a
code generator (raster): items 1–3 of "JIT primitives the staging
mechanism must provide" in `doc/architecture.md` (notes K and M). Changes
are in `klara.stage` (validity memo, speculative executables, frame-state
checks, feedback), `klara.eval` (marker frame, `:stage/deopt`,
`materialize`, host `deopt!`) and `klara.expand` (built-in macros
`speculate`, `deopt!`). No Clojure Java sources were consulted.

```

clojure -X:spec-diff   # unchanged: 69 programs, 65 agree, 4 known differences
```

## 1. What was built

| Piece | Where | What it does |
|---|---|---|
| per-root validity | `stage/valid-in?`, `prepare` | at install, guards split into world guards and runtime guards; the world verdict is checked once per (executable, root) and memoized on the installed executable (4 most recent roots, weak references, compared by `identical?`) |
| entry path | `stage/enter`, `term-code-id` | CodeId found through a 512-slot identity table, not `c/code-id`'s structural memo; stats are `LongAdder`s instead of a `swap!` on the cache per entry; new counters `:revalidations`, `:deopts` |
| speculative executables | `stage/speculative` | `:klara` residual closure, or `:run` host fn, plus `:generic` (the fn term) and `:frame-states`; the certificate carries a digest of both (`:frame-state-mismatch` on tampering) |
| frame-state checks | `stage/frame-states-error` | at install: generic CodeId matches; every path names a node; environment length = captures + `scope-depth` at the position; frame templates match their node's op; no authority in a `[:const ..]` slot |
| surface | `speculate`, `deopt!` | `(speculate test fast i [live ..])` = `(if test fast (perform :stage/deopt i [live ..]))`: nothing allocated on the fast path; `fast` stays in tail position, so `recur` works |
| marker frame | `eval/exe-frame` | a speculative Klara residual runs under `{:tag :exe :exe ..}`; not pushed again when already on top (self tail call), so loops through the hook stay in constant space |
| deopt in the machine | `eval/deopt-in-machine` | drops the residual's frames down to the marker, refusing to drop `:branch :fork-run :fork-scope :direct` and staging frames; then `materialize` |
| deopt from host code | `eval/deopt!` = `stage/deopt!` | throws a signal caught by `run-executable`, which materializes over the caller's continuation with the generic closure's basis and mint |
| materialization | `eval/materialize` | builds `[:eval term env k]` or `[:ret v env k]` from a frame state and live values (format below) |
| feedback | `stage/observe!`, `observed`, `feedback`, `join-feedback`, `speculate?` | `ConcurrentHashMap` of `AtomicLong`s keyed by `[[code-id site] kind]`; monotone, saturating at `feedback-cap` (10⁶); the deopt hook records `:deopt` at `(CodeId, (:site fs))`; `speculate?` = fewer than 3 deopts at the site |

### Frame states

```
{:site s                  ; feedback site within the CodeId
 :at [:eval path]         ; evaluate the generic term at path, or
   | [:ret slot]          ;   return a value into :kont
 :env [slot ..]           ; generic locals, outermost first: captures, params, binders
 :kont [frame ..]}        ; generic frames, outermost first, pushed on the caller's k
```

Slots: `[:live j]`, `[:const v]`, `[:local j]` (a local already rebuilt),
and for allocations the specialized code elided: `[:closure path]`,
`[:letrec path i]` (one shared environment per letrec group, as T0's own
letrec), `[:instance mode]` (a fresh handler instance), `[:vector [slot ..]]`.
Frames: `:let`, `:if`, `:list` (`:vals` computed so far; `:todo` is
recomputed from the node) and `:handle` (`:instance`, `:clauses`, `:return`),
each with `:env n` (prefix of `:env`), or with a slot vector and `:fn term`
for an inlined caller's frame. Paths are `get-in` paths from the fn term,
so a frame state stores positions, not code.

Virtual-object descriptors were cheap, so they are included: closures,
letrec groups, handler instances and vectors. Maps, records and general
scalar replacement are not (see §4).

## 2. Decisions

1. **The verdict is memoized on the installed executable, not in the
   root.** Roots stay plain values. No global table maps roots to anything,
   so publication cannot do work for executables (R1 by construction), and
   a dropped root's memo entries clear themselves (weak references).
2. **Validity memo size 4, MRU.** It covers the R4 case (old and new pinned
   fibers alternating) without unbounded growth. A fifth root evicts the
   least recent verdict, which is then recomputed. It is not lost.
3. **Revalidation is O(world guards), not O(changed cells).** M-P2 suggests
   consulting the change log between two roots. That was not needed to
   remove the per-entry cost, and the root keeps no change log.
4. **Runtime guards stay per entry.** `[:arg]`, `[:captures]`, `[:statics]`
   and `[:unhandled]` depend on the call, not the root.
5. **Deopt replaces the residual's whole activation.** The marker delimits
   the frames of the residual. Everything above it is dropped, and
   everything the generic code needs is in the frame state. This is V8's
   model, where one optimized frame becomes N interpreter frames, and it
   lets `speculate` appear in any position, not only in tail position.
6. **Frames that hold authority or staging state are deopt barriers.**
   Dropping a residual's `:branch` frame would leave its fork group open,
   and rebuilding one would duplicate it. Such a deopt is a detected stage
   error (tested). A fork opened by the *caller* lies below the marker, is
   untouched, and settles normally (tested).
7. **Authorities enter frame states only as live values.** An authority
   constant would be revived by every deopt, so install refuses it. A live
   authority is a reference, and S6 makes references freely aliasable.
   Linearity is in the store, so the generic code continuing after a
   `spend!`/`consume!` uses the authority exactly as the original run
   would.
8. **Frame states are indexed per executable.** The residual passes
   `(deopt! i live)`, and the frame state lives in the executable, inside
   the certificate digest. Residual code stays closed and small, and a
   frame state cannot be swapped without re-certification.
9. **The checker is still `:klara/trusted-handwritten`.** The structural
   checks (scope shape, node kinds, no authority constants) run at install
   for every speculative executable. The semantic obligations remain
   trusted: the fast path agrees with generic under the guard, and the
   frame state is *exact*.
10. **Feedback lives in the cache, outside the world** (deleting it changes
    no result), and only deopts are recorded. That is the minimum for a
    decision, and it keeps the success path free of counters. Poisoning is
    the monotone counter reaching the threshold.
11. **The pre-S7 entry decline stays.** A host executable returning
    `klara.eval/deopt` still replays from entry. It is sound there because
    host executables perform no Klara effect before declining. S3's fusion
    relies on it.

## 3. Measurements

`clojure -Sdeps '{:aliases {:bench {:extra-paths ["test"] :jvm-opts ["-Xss16m"]}}}' -M:bench -m klara.stage-bench <out>`
(`test/klara/stage_bench.clj`). `f` mentions k globals on a branch that is
never taken, so it has k world guards and a cheap body. A T0 loop calls it
20 000 times. "Before" ran the same bench against the pre-S7 `src/`
(`git archive`). Raw files: `experiments/s7-entry/before.txt`, `after.txt`.
JDK 25, one run each, medians of 15.

| world guards | `enter`, before (ns) | `enter`, after (ns) | loop iteration with exe, before (µs) | after (µs) | loop, no cache (µs) |
|---|---|---|---|---|---|
| 0 | 290 | 182 | 4.2 | 4.9 | 4.2 / 5.3 |
| 8 | 2 052 | 184 | 8.2 | 6.0 | 4.6 / 5.8 |
| 32 | 7 462 | 191 | 15.8 | 7.3 | 7.2 / 7.5 |
| 128 | 29 087 | 190 | 46.9 | 14.3 | 13.8 / 16.5 |

- Entry under an already-validated root is now constant (~190 ns), down
  from ~230 ns per world guard. The executable with world guards now costs
  the same as one with runtime guards only.
- Before S7, `enter` with runtime guards only also grew with term size
  (683 → 1 249 ns from k = 8 to 128). That was `c/code-id`'s memo hashing
  the argument list. The identity table removes it.
- The no-cache loop varies by ±1 µs between JVM runs (a separate 2×2 run
  of k = 8 gave 5.6–6.4 µs for both trees), so the 0- and 8-guard
  differences in the last column are noise. The loop still grows with k
  without any cache, because `resolve-global` re-checks the resolved
  entry's recorded reads on every resolve (S1 gap "a pending check costs
  O(reads) on every resolve"). That is the same per-root fact and could
  use the same memo; it was not changed, because it is T0's reference
  path.

Validity counts (tests): 1000 entries under one root give 1 revalidation.
200 publications of a symbol that 2000 executables read cause no cache
work. R4 with 4 reader threads and a writer gives 2 revalidations for 800
entries.

## 5. Gaps and open decisions

- **No generator emits frame states.** All residuals and frame states in
  the tests are written by hand against the expanded terms. M-P3's
  `(speculate guard fast slow)` *inside `code`*, with the specializer
  filling in the slow side, needs a `reflect-state` operation (K R3): the
  generator turns its present T0 state into a frame state, keeping every
  value that state needs live. Exactness is an unchecked obligation today.
- **Partial escape analysis.** Descriptors exist for closures, letrec
  groups, handler instances and vectors only. Maps, sets, records,
  authority-free host objects and nested virtual objects under identity
  (K §4) are the next step, and so is the PEA pass that would produce
  them.
- **Inlined callers** are supported in the format (`:fn` and slot-vector
  `:env` on a frame), but no test inlines a caller, and install checks
  their shape less strictly.
- **Deopt behind a host frame** (a residual's callback run by `map`) is an
  error. The marker is in `*outer-k*`, and resuming T0 would need the host
  frame converted. This is EF5's boundary again.
- **Deopt barriers.** A residual that opens a fork or a `direct` scope
  cannot deopt inside it. Supporting that needs frame templates that adopt
  the existing branch context rather than rebuilding it.
- **Revalidation cost under many candidates.** The first entry under a new
  root checks every candidate of the CodeId (2000 in the R1 test). M-P7's
  cap of about 4 entries per function and aging (architecture item 7) are
  not done.
- **The marker frame** is visible to every frame walk (`all-frames`,
  `resume-blocker` skips its `:exe` key). A continuation captured inside a
  residual and resumed elsewhere keeps the marker, so a deopt from there
  still finds its executable. Multi-shot resumption through a deopt is not
  tested.
- **Feedback is deopt-only.** Call targets, argument shapes and branch
  counts (M-P1's lattice) are not collected. Feedback in forks
  (parent snapshot plus overlay, joined on adoption) has only the
  `join-feedback` operation. Soft deopts, the 15/100 deopt-cycle budget
  and per-guard poisoning (as opposed to per-site) are not done.
- **OSR, install by compare-and-set against a moving root (M-P5), and
  `run` that compiles** depend on a code generator and were out of scope.
- **The resolve-path pending check** (§3) could reuse the per-root memo.
  Left alone because it is T0's reference path.
