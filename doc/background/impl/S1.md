# S1: first runtime slice (2026-10-27)

Implements step S1 of `06-architecture-synthesis.md` §7 in `src/klara/`:
core syntax, worlds, basis-specific execution, the expander producing core
terms, the T0 reference interpreter and the specialization cache. Hosted on
Clojure 1.12; the expander is ported from lambda-join `v0` together with X1,
relicensed to Apache-2.0. No Clojure Java sources were consulted. The code
calls only public host API: `requiring-resolve`, macro vars as functions, and
`clojure.lang.Reflector` for static members.

```
clojure -X:test        # 29 tests, 143 assertions, 0 failures
```

## 1. What was built

| `klara.world` | immutable roots `{:version :defs :rdeps}`, recorded reads, `publish!` (one CAS), `commit!` (optimistic, rebases when reads hold), `fork` (pins the parent root), fibers with `raise-basis!` | 171 |
| `klara.expand` | v0's scope-set expander (flip discipline, largest-subset resolution, `qq`) emitting **core terms** with de Bruijn indices; the world as the macro environment; recorded reads including **negative lookups**; sub-expansion memo with `form-key`/`alpha-key` | 550 |
| `klara.eval` | T0: a CEK machine with data frames; lexical and dynamic handlers; reference handlers for `:host/*`, `:world/*`, `:exn/raise`; closures as host IFns; `specialize` as partial application; entry hook for the cache | 342 |
| `klara.defs` | `define!` (expand → evaluate → commit), `invalidate!` (red-green with early cutoff, one transaction, one CAS), `lookup`, `eval-in` a fiber | 140 |
| `klara.stage` | executables keyed by (CodeId, assumption set), guards checked on entry, generic fallback, lazy and swept invalidation from world reads, certificate-checked `install!`, the trivial residual | 178 |

Pipeline of one definition: `expand-recorded` reads the world only through
`klara.world/entry`, which notes `[:absent s]`, `[:def s]`, `[:macro s h]`
and `[:value s h]`. The resulting term gets a CodeId, and T0 evaluates it
under that root with `:mint nil`, recording the world values it consumes.
`commit!` then publishes the entry. A later edit makes dependents whose reads
broke **pending**: resolving one raises `:pending`. `invalidate!` re-checks
the dependents and publishes all repairs together in one CAS:

- *green*: all reads still hold;
- *cutoff*: same CodeId, so the value is kept and only the reads are
  refreshed;
- *stale*: re-evaluated.

## 2. Decisions the docs left open

1. **Term shape.** Terms are maps with `:op`. De Bruijn index 0 is the
   innermost binder. Binders push in source order, so the *last* fn
   parameter is index 0. `fn` has `:arity` and `:rest?` and only one arity.
   Application is `:app`. `do` and multi-binding `let` become nested `let`s
   with hidden binders.
2. **`handle` always binds its instance**, in both modes, so indexing is
   uniform. `(perform nil op …)` is *ambient*; the ambient namespaces are
   `world host exn time`. A dynamic `handle` may only handle ambient
   operations, and a lexical one only user operations. The core checks both
   rules.
3. **Clause convention.** A clause is a function of the operation's
   arguments plus the continuation `k`. An optional `:return` clause exists.
   Handlers are deep. Continuations are vectors of data frames, so T0 allows
   multi-shot resumption. The authority restriction of RFC 0001 is not yet
   enforced.
4. **Exceptions.** The operation is `:exn/raise`. Host throwables from prims
   and host calls become `:exn/raise` at the call site. An uncaught raise
   leaves T0 as a host exception. `try/catch` lowers to a dynamic handler
   that tests classes in order and re-raises when none matches.
5. **Host boundary.** A Klara closure called *by* host code runs in a nested
   machine. A lexical perform from inside it cannot reach its handler and
   raises a detectable error (EF5). Exceptions do cross the boundary.
6. **Global-resolution policy, and with it basis-specific execution.**
   Closures created at run time keep their *creation* basis (v2 §3 default).
   World definitions are stored as **open** closures (basis nil), which run
   under the basis of whoever resolves them. The machine has a `:mint`
   register: the basis stamped on new closures. Definition-time evaluation
   runs with `:mint nil`, so letrec self-references stay open too. This
   removes the shared host namespace without per-basis instantiation caches.
   One `g` value runs under two bases (`r4_test`).
7. **Read kinds and the firewall.** A runtime reference is the late-bound
   read `[:def s]`, which a body change of `s` never breaks. Only macro
   reads, value reads and negative lookups propagate. This replaces v0's
   arity firewall.
8. **Value identity.** `:value-id` equals the CodeId, or a hash of the CodeId
   plus the definition-time value reads when there are any (a Unison-style
   deep hash). `[:macro]` and `[:value]` reads compare value-ids, so
   `(def derived (* 2 base))` is recomputed when `base` changes.
9. **Visibility.** Invalidation is explicit, never done at write time (C §4.3).
   Until it runs, broken dependents are *pending* (refused) rather than stale
   (silently run). This is v2 §6's "visible pending state".
10. **Free-identifier order.** Special forms come first, then locals, the
    world (recorded), built-in `qq`, prims (operator position only),
    clojure.core host macros and clojure.core host functions. Anything else
    is an expansion error, as in Clojure. The one forward reference allowed
    is the name being defined.
11. **The host is effects, not a form.** `:host/call`, `:host/var`,
    `:host/static`, `:host/static-field` and `:host/class` are ambient
    operations. The reference handler is the oracle, and a dynamic handler
    can mock it (tested). `prim` is a fixed table of clojure.core functions
    under the same names.
12. **Executables come in two kinds.** An executable is either Klara code
    entered *in the same machine* (`:klara` closure plus `:prefix` statics,
    which the trivial residual uses) or a host function (`:run`). A host
    function is a host frame, so it must be effect-free. The first R3 run
    found this: a host-wrapped residual of an effectful function failed at
    the boundary.
13. **Guards.** The guard kinds are `[:world s value-id|:absent]`,
    `[:arg i pred]`, `[:captures locals]` and `[:statics vals]`. The cache
    hook runs on closure and partial-application entry. Captures are part of
    the key because one CodeId has many closures.
14. **Certificates.** A certificate holds `:code-id`, `:assumptions`,
    `:checker`, `:checker-version`, `:provenance` and `:digest`. Install
    rejects six cases: a missing certificate, a CodeId mismatch, an
    assumption-set mismatch, an untrusted checker, missing provenance, and a
    digest mismatch. The trusted checkers are `:klara/trivial` and
    `:klara/trusted-handwritten`, both placeholders until S3.
15. **Publication.** The root is one atom and `publish!` is a CAS loop.
    `commit!` rebases onto a newer root when every recorded read still holds,
    which is v0's transactor payoff. The reverse-dependency index lives in
    the root and is updated in proportion to the entry's own reads, not its
    fan-out (R1-shaped). A fork pins its parent's root as `:parent`.
16. **Raising inside running code.** `(perform :world/raise-basis)` moves the
    fiber's pin and is seen by later top-level evaluations and by
    `:world/resolve`. Closures that are already running keep their creation
    basis, because a closure is a value.
17. **`quote` strips scopes.** It is datum quotation; syntax values are not
    yet a separate kind.
18. **Expansion context.** Each definition gets a fresh context, with scope
    ids per context. The CodeId does not depend on either (tested), and the
    term contains no gensyms.
19. **The memo key under de Bruijn output.** `alpha-key` replaces locals by
    their index at the call site. One consequence: with index output, the
    bare-form key collides only when the same form resolves to *different
    indices*. v0's shadowing example `(let [x 1] … (let [x 2] (inc1 x)))` no
    longer collides at all, so the test uses a binder at a different depth.
20. **`:world/define`** publishes a raw value. Its value-id is
    identity-based.

## 3. Test results

`clojure -X:test`: 29 tests, 143 assertions, 0 failures, 0 errors.

- **X1 (i)–(v)** (`x1_test`):
  - (i) after a redefinition `f` is pending; invalidation reports it stale
    and re-expanded, and `(f 3)` goes from 6 to 9.
  - (ii) a refactor that keeps the output cuts off: two expansions, the
    value is `identical?`, and the history is unchanged.
  - (iii) a fork's edit leaves the parent at 6.
  - (iv) a pinned fiber sees 6 until `raise-basis!`.
  - (v) the bare-form key gives `[2 3]` (wrong), `alpha-key` gives `[2 2]`
    with 2 entries, and closed forms share one entry. Fresh expansions with
    different scope counters and binder names give the same CodeId.

  Also tested: macro-through-macro, a transformer reading a world value
  (only the user `h` goes stale; the macro's late-bound read stays green),
  **negative lookups** (defining `inc` first as a macro, then as a function,
  re-expands `g` each time), and definition-time value reads.
- **R3** (`stage_test`): 10 programs, covering effects, specialize, guard
  failures and exceptions, give the same results with no cache, with a
  populated cache (hits and fallbacks both nonzero), and after `clear!`.
  After editing `sq`, the stale cache still gives the results of a run
  without cache, the sweep drops exactly the 2 executables that read `sq`,
  and the old root still gets the old answers.
- **R4** (`r4_test`): the X1 leak scenario now passes (the parent's `g 3` is
  4, the fork's is 30, and both share one `g` value). Two forks and four
  pinned fibers (old and new on each) read `(g 3)` 200 times each, while a
  writer thread publishes to both worlds. Every read matched its version
  (6/90/6/102 for the function, 6/9/6/2 for the macro). Raising and the
  fork's pinned parent behave as specified.
- **T0 corpus** (`eval_test`): closures, varargs, closures passed to host
  `reduce` and `map`, mutual and self tail calls over 10⁵–10⁶ iterations in
  constant space, state, a generator, abort, multi-shot `amb`, nested
  handlers (an inner handler of the same operation does not intercept: EF4),
  deep handlers, an instance used outside its extent, exceptions (re-raise,
  uncaught, across host callbacks), EF5, a dynamic mock of `:host/call`,
  the `:world/*` handlers, and s-m-n for `specialize`.
- **World** (`world_test`): 8×50 concurrent publications with no lost update;
  every observed root is consistent. Also tested: commit rebase and retry,
  forks and fibers, and CodeId α-equivalence and map-order independence.

T0 speed for orientation: a `loop` of 10⁶ iterations takes about 3 s, roughly
3 µs per iteration. That is fine for a specification interpreter.

## 4. Known gaps

- **Surface:** no multi-arity fns, `finally`, `.`/`new` interop, `case*`,
  `set!`, `var` or metadata. `recur` is not checked for tail position, and
  the scan that decides whether a fn needs a recur target is conservative.
  Host macros come only from clojure.core and are unrecorded host reads
  (Q12).
- **Staging values (v2 §6):** no syntax values, `quote-syntax`, code values,
  `close`/`run`/`lift`, scope-extrusion checks or expansion-context
  capabilities. Macros are plain transformer closures.
- **Effects:** operations are not classified tail/abort/general, and there is
  no authority accounting, fork-resume restriction or deferred irreversible
  effects (RFC 0001). The `:time/*` operations are not implemented.
- **Bases:** an open closure inside a data structure, invoked from host code
  outside any machine, falls back to the dynamic `*basis*` and then to the
  empty root. A pending check costs O(reads) on every resolve.
- **Re-execution:** a lost CAS race re-evaluates the definition, repeating any
  definition-time effects. `invalidate!` likewise reruns its whole
  transaction when it conflicts.
- **Stage:** there is no real specializer, partial evaluation, PIC, profile,
  reoptimization budget or deopt-loop detection (C §4.3 item 6, R5).
  Certificates are placeholders. Host executables are effect-free by
  obligation only; nothing checks it.
- **Expansion cache:** the memo lives for one session. There is no
  content-addressed cross-fork cache (C §4.4) and no rotating re-expansion
  check (O4).
- **Gates not measured:** R1, R2 and R5–R8. X1's (vi) showcase measurement
  was not ported, because v0's corpus depends on v0's host evaluation.
