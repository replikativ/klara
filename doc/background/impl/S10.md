# S10: affine regions, first sound fragment (2026-10-28)

**S10 is complete for the bounded implementation described here.** The
store, T0 owned effects and capture restriction, lexical cleanup, surface,
parameter contracts, EDN checker, checked erasure and one licensed JVM
in-place loop are implemented. Formal semantics/proofs and extensions are
listed below. No Clojure Java implementation sources were consulted.
No changes were made to `compile/emit.clj` or `compile/pe.clj`.

## Built

`klara.authority` adds `:owned` to the existing store, generation counters,
context substitution, fork derivation, and settlement. The payload is
`{:cell value :share rational :lent {loan-id rational} :permission kind}`.
`kind` is `:write` or `:read`; a loan with numerical share 1 still cannot
write. All allocated cells initially have share 1 and write permission.

Host API used by the machine integration:

| API | Behavior |
|---|---|
| `(op! :own/alloc [value] frames)` | mint a full owned cell in the current branch context |
| `(op! :own/read [token] frames)` | read with any positive available fraction |
| `(op! :own/update [token f & args] frames)` | functional replacement under an exclusive update lease; return the token |
| `(op! :own/move [token] frames)` | atomically settle the old full token and mint its replacement in the running context |
| `(op! :own/freeze [token] frames)` | settle a full token and return its persistent value |
| `(op! :own/drop [token] frames)` | settle a full token; return nil |
| `(borrow-owned! token frames)` | lend the available share (including fork fractions) as a lexical read loan |
| `(borrow-owned! token q frames)` | atomically debit q and mint a read loan; return its token |
| `(return-owned! loan)` | trusted scope-exit cleanup; restore the loan's exact share and settle its token |
| `(with-owned-borrow token q frames body)` | host reference for lexical cleanup via try/finally |
| `(full-owned-held? frames)` | query live full permission in the running context chain |

`return-owned!` is the cleanup primitive, not a program-level operation:
the evaluator must keep the loan token in a lexical cleanup frame.
`with-owned-borrow` is for host callbacks. Using it as the implementation
of Klara `borrow` would introduce an opaque host boundary and prevent
capturing effects across that boundary.

Updates call `f` once outside `swap!`, while the cell is `:advancing`.
Concurrent reads/writes and reentrant uses fail closed during that lease.
A failed functional callback publishes no cell change and reopens the
token. The caller must supply a functional callback; host mutations
performed inside it are outside the value-semantics guarantee.

Borrow, move, return and settlement use atomic store transitions; racing
borrowers cannot obtain more than the available fraction. Borrowing can
split any available fraction (including a read loan). Write, move,
freeze and drop require full write permission with no outstanding lends.
Rejected operations do not consume permission. Freeze and drop are
consuming operations, so repeating either is an error.

Fork entry rejects a full owned share held in the context chain, even
when no branch uses it. This query scans live store tokens in those
contexts; there is no reachability-based or implicit lexical drop yet.
Remaining read fractions split by positive fork
weights (equal by default); zero and floating-point weights are refused
for owned shares so splitting preserves exact rational mass.
Second-shot derivation may lend a read fraction for the shot's duration;
full permission is refused both by `resume-blocker` and at derivation.
Children settle and restore the parent's fraction on adoption, discard,
and cancellation. Outstanding child loans close recursively at fork exit,
so an escaped loan cannot survive adoption with duplicated permission.
Fresh branch-owned cells follow the existing adopt/rescope or discard
rules. Group operations retain S6's single-machine assumption; they are
not atomic across host threads.

## S10b milestone 2: effect admission and machine loans

The `own` ambient namespace now dispatches through `auth-perform`.
Admission is structural (`klara.effect-class`): a fixed-arity Klara clause
may ignore k, or use it only as a direct final call through lets/ifs.
Other clauses, including unknown host closures, cannot capture while the
context chain holds a full share. No declaration is trusted. Reference
handlers remain direct calls. The store query includes suspended host
machines and advancing update leases; second shots also check the running
context. This deliberately conservative fragment can reject more complex
but semantically tail-resumptive clauses.

`:own/borrow` invokes a Klara body with a read loan of the available share and a
machine cleanup frame. Normal return, exception and handler exit return
the loan. Captured loan scopes get a cleanup frame around the clause;
escaped continuations cannot revive a closed loan. Fork frames nested in
an abandoned captured borrow are closed before its loan is returned.

## S10b milestones 3–4: surface and first static fragment

Owned operations and lexical `borrow` now expand to `:own/*` effects.
Function parameters accept `^:own` (full-share contract), `^:move` (fresh
callee token, caller token invalidated) and `^:borrow` (lexical read loan
returned on callee exit). These boundary contracts stay dynamic.

`defaffine` and `def ^:affine` check before publication. `klara.affine/check`
accepts core terms, producing EDN rules indexed by source paths and resource
identities; inferred mode returns nil on failure, declared mode throws a
path and diagnostic. `verify!` recomputes the derivation, rather than
trusting user-supplied facts. The first fragment covers local allocations,
reads, pure functional updates, moves, settlement, lexical borrows, matching
branches and direct-entry self-tail loops that preserve ownership at back edges.
Owned results cannot escape; every allocated place must settle. Dynamic
boundary contracts, arbitrary effects and calls are outside this fragment.
The same checker serves both modes. This is executable finite evidence,
not an ansatz soundness proof.

## S10b milestone 5: checked erasure and isolated JVM emission

`klara.compile.affine-erase/erase` recomputes a supplied derivation before
emitting any check-free code. Boxed cells preserve functional updates and
persistent read snapshots, including aliases, moves and lexical borrows.
A narrower representation licenses a private `long[]` for literal Long
vectors when every update is exactly `(fn [v] (assoc v i (inc (nth v i))))`
with a fixed, in-bounds i. Reads/freeze copy to persistent vectors; the
initial persistent value is never mutated. Transfers use the boxed path.
Every update of the buffer is therefore covered by both a share derivation
and a checked callback shape. Arbitrary callbacks stay functional.

The only connection to the existing compiler is a marked one-line wrapper
hook in `compile/core.clj`. It selects this isolated emitter for accepted
owned definitions and delegates other definitions to the ordinary pipeline.
`emit.clj` and `pe.clj` are untouched. Long parameters are unboxed only on a
Long-guarded entry; other inputs use generic arithmetic. Existing entry
contracts reject dynamic exception handlers and wrong arity before effects.
A separate tested certificate binds the generic CodeId and recomputed
EDN derivation. This trusted compiler is not a kernel proof.

Differential tests compare T0, boxed erasure and licensed buffer erasure,
including persistent snapshots before/after updates, moves, nested loans,
loop results, non-Long inputs, cache installation and tampered derivations.

## S10b milestone 6: adversarial tests and allocation measurement

`test/klara/affine_test.clj` adds language rejection of double settlement,
use after move, write through a loan, fork holding a full share and general
effect capture holding a full share. It tests escaped continuations,
normal/exceptional/abortive loan cleanup, nested forks cancelled inside a
captured loan, nested lexical loans of fork fractions, parameter contracts,
callback exceptions and branch contexts. Forty seeded programs (seed 105)
compare ordered persistent snapshots against an independent functional
accumulator, T0, boxed erasure and buffer erasure (AF1/AF3). Cache install,
non-Long inputs, numeric loops and tampered derivations are also tested.

The static fragment has no external effect operations; its AF3 traces are
ordered value observations, with empty output traces. Opaque host inputs
are separately tested for equal effect traces through T0 fallback. Exact
immutable data classes are checked before erased entry: arbitrary host
implementations of collection/number protocols could otherwise perform
untracked effects. This is a retained boundary guard, not a static claim
about arbitrary host objects. Owned argument contracts stay in T0.

The allocation experiment uses the public `ThreadMXBean` counter and
checks results before accepting samples:

```
clojure -M -e '(load-file "experiments/affine/bench.clj") (klara.affine-bench/run!)'
```

OpenJDK 25.0.1, 300 warmup calls × 100,000 iterations; nine samples per size.
Median bytes per call: **656 at 0 iterations, 680 at 1,000, 680 at
1,000,000**. The slope from 1,000 to 1,000,000 is **zero bytes**. The
24-byte difference at zero is fixed result boxing. Entry guards, the
buffer and persistent result still allocate. This is one measured loop,
not a blanket allocation guarantee. Raw samples are in
`experiments/affine/s10-results.edn`.

## Remaining work

- Extend the ansatz semantics with the owned store and prove AF1–AF3;
  all implementation correctness evidence here is finite testing.
- Broader static inference, arbitrary calls/effects, general recursive
  resource protocols, owned argument erasure and named lifetimes.
- In-place updates beyond the verified literal Long-vector callback;
  arrays supplied by callers, collection transients, authority-bound edit
  tokens (including PSS), JS/native and metacarp lowering.
- One-shot general effects, strict module defaults and quantitative
  accounting remain later design under RFC 0005 §10–11.

Explicit settlement is required; there is no reachability-based implicit
last-use drop. Store context queries intentionally reject a fork/capture
when an otherwise unreachable live full share remains in that context.
