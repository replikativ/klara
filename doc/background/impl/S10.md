# S10: owned authority store, first milestone (2026-10-28)

**Partial S10: scope item 1 is built. Items 2–6 are unfinished.** The
implementation stops before exposing owned operations as language effects.
No changes were made to the compiler, `stage.clj`, or `eval.clj`, including
its deopt machinery. No Clojure Java sources were consulted.

## Built

`klara.authority` adds `:owned` to the existing store, generation counters,
context substitution, fork derivation, and settlement. The payload is
`{:cell value :share rational :lent {loan-id rational} :permission kind}`.
`kind` is `:write` or `:read`; a loan with numerical share 1 still cannot
write. All allocated cells initially have share 1 and write permission.

Host entry points for the next integration milestone:

| API | Behavior |
|---|---|
| `(op! :own/alloc [value] frames)` | mint a full owned cell in the current branch context |
| `(op! :own/read [token] frames)` | read with any positive available fraction |
| `(op! :own/update [token f & args] frames)` | functional replacement under an exclusive update lease; return the token |
| `(op! :own/move [token] frames)` | atomically settle the old full token and mint its replacement in the running context |
| `(op! :own/freeze [token] frames)` | settle a full token and return its persistent value |
| `(op! :own/drop [token] frames)` | settle a full token; return nil |
| `(borrow-owned! token q frames)` | atomically debit q and mint a read loan; return its token |
| `(return-owned! loan)` | trusted scope-exit cleanup; restore the loan's exact share and settle its token |
| `(with-owned-borrow token q frames body)` | host reference for lexical cleanup via try/finally |
| `(full-owned-held? frames)` | query live full permission in the running context chain |

`return-owned!` is the cleanup primitive, not a program-level operation:
the evaluator must keep the loan token in a lexical cleanup frame.
`with-owned-borrow` is for host callbacks. Using it as the implementation
of Klara `borrow` would introduce an opaque host boundary and prevent
capturing effects across that boundary.

Updates call `f` once outside `swap!`, while the cell is `:advancing`.
Concurrent reads/writes and reentrant uses fail closed during that lease.
A failed functional callback publishes no cell change and reopens the
token. The caller must supply a functional callback; host mutations
performed inside it are outside the value-semantics guarantee.

Borrow, move, return and settlement use atomic store transitions; racing
borrowers cannot obtain more than the available fraction. Borrowing can
split any available fraction (including a read loan). Write, move,
freeze and drop require full write permission with no outstanding lends.
Rejected operations do not consume permission. Freeze and drop are
consuming operations, so repeating either is an error.

Fork entry rejects a full owned share held in the context chain, even
when no branch uses it. This query scans live store tokens in those
contexts; there is no reachability-based or implicit lexical drop yet.
Remaining read fractions split by positive fork
weights (equal by default); zero and floating-point weights are refused
for owned shares so splitting preserves exact rational mass.
Second-shot derivation may lend a read fraction for the shot's duration;
full permission is refused both by `resume-blocker` and at derivation.
Children settle and restore the parent's fraction on adoption, discard,
and cancellation. Outstanding child loans close recursively at fork exit,
so an escaped loan cannot survive adoption with duplicated permission.
Fresh branch-owned cells follow the existing adopt/rescope or discard
rules. Group operations retain S6's single-machine assumption; they are
not atomic across host threads.

## Validation

including all executable guide and example transcripts.
`clojure -X:spec-diff`: **1 test, 138 assertions, 0 failures/errors**;
69 programs, 65 agreements and the existing four documented differences.

`test/klara/owned_test.clj` covers lifecycle and generations, use after
move, repeated settlement, full and partial loans, nested loans, writes
through borrows, callback failure and reentrancy, full-share fork and
shot rejection, read forks and nested forks, adopted escaped loans,
branch contexts, concurrency, and a seeded 200-step walk. The walk
compares cell observations to a persistent functional accumulator and
checks total live share after every operation. This is finite store-level
AF1/AF4 evidence; it does not establish language-level check erasure.

The guide's functional example is executable; planned affine syntax is
marked `:norun`. The RFC obligation table distinguishes these store tests
from the still-open language and proof obligations.

## Why this stops at item 1

Item 2 requires verified operation classification at reference-interpreter
dispatch, plus lexical cleanup across continuation capture and unwind.
The existing T0 dispatcher gives arbitrary handler closures a `Cont`;
its second-shot check alone is too late for RFC 0005 Q2. The compiler's
lexical clause classifier does not currently enforce this in T0. Exposing
`own` without the restriction would allow a general handler to capture a
live full share. Completing that change and its cleanup interaction is
too large for this milestone, so the owned surface remains unavailable.

- Add a borrow cleanup frame with normal, exceptional and abortive exit

## S10b milestone 2: effect admission and machine loans

The `own` ambient namespace now dispatches through `auth-perform`.
Admission is structural (`klara.effect-class`): a fixed-arity Klara clause
may ignore k, or use it only as a direct final call through lets/ifs.
Other clauses, including unknown host closures, cannot capture while the
context chain holds a full share. No declaration is trusted. Reference
handlers remain direct calls. The store query includes suspended host
machines and advancing update leases; second shots also check the running
context. This deliberately conservative fragment can reject more complex
but semantically tail-resumptive clauses.

`:own/borrow` invokes a Klara body with a whole-share read loan and a
machine cleanup frame. Normal return, exception and handler exit return
the loan. Captured loan scopes get a cleanup frame around the clause;
escaped continuations cannot revive a closed loan. Fork frames nested in
an abandoned captured borrow are closed before its loan is returned.
