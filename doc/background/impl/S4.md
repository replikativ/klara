# S4: staged code values, the Klara REPL, transcript tests (2026-10-28)

Implements the staging part of `01-core-v2.md` §6 in T0. Code values are
built with `code`, spliced with `esc`, run with `run` and populated with
`lift`. Let-insertion is provided by `genlet` and `with-genletrec`. A
dynamic scope-extrusion check follows BER MetaOCaml. Alongside this, S4 adds
an interactive REPL (`clojure -M:repl`, prompt `k=>`) and a harness that runs
REPL transcripts in markdown as tests. The guide chapter is
`doc/guide/05-staging.md`, and six worked examples are in `examples/staging/`.
No Clojure Java sources were consulted.

```
clojure -X:test        # 49 tests, 3588 assertions, 0 failures
```

The 49 tests are the 36 of S1–S3, 7 in `staging_test`, 2 in
`transcript_test` (one of which runs every transcript in `doc/guide/` and
`examples/`), and the guide branch's `world_ops_test` and additions.

### How code is built

Evaluating `(code e)` does not interpret `e`. The machine switches to mode
`:build` and walks `e`'s core term at level 1, returning an s-term. The
main steps:

- A binder at level ≥ 1 gets fresh `Gen` names. Its environment slot holds a
  `CodeVar`, so a reference at level ≥ 1 emits the variable, and a reference
  from level 0 (inside `esc`) yields the variable's code.
- A level-0 value referenced at level 1 is lifted (implicit CSP).
- `esc` at level 1 evaluates its body at level 0 and splices; at higher levels
  it is rebuilt.
- The build frames (`:blist`, `:locus`, `:code-done`, `:splice`, `:wrap`,
  `:locus-rec`, `:locus-rec-bind`) are ordinary data frames on the
  continuation, so effects, multi-shot resumption and deep handlers keep
  working inside generators.

**Liveness.** A generated name is alive iff a frame declaring it is on the
continuation, or on a continuation suspended behind a host frame. This is BER
N101's stackmark check, phrased for a CEK machine. A splice checks that every
free name of the spliced code is alive. `run` requires closed code
(`s->core` refuses any free name).

**genlet** scans the frames from the top. The candidate insertion point is
updated at each `:locus` frame, and the scan stops at the first frame that
binds a free name of the code: a binder frame, a locus holding an earlier
inserted name, or a genletrec locus. The result is BER's "as high as scope
allows", tested against the placements in `ber-metaocaml-153/test/genlet.ml`.
Loci are the top of every `code` and the body of every generated binder,
except letrec inits, which must stay `fn` terms.

## 2. Decisions taken (not fixed by the docs)

1. **Generated terms use names.** Index terms cannot be spliced under binders
   without shifting, and BER prints names. Core stays de Bruijn. `run`
   converts with `s->core`, and the free-name case of that conversion *is*
   the closedness check.
2. **`code` and `esc` are core forms; `run`, `lift`, `genlet` and the
   genletrec locus are ambient operations `:stage/*`.** Brackets change
   binding structure, so they must be forms. The others are effects: a
   dynamic handler can instrument or replace them (tested with
   `:stage/genlet`), and the core grows by two forms, not six. The surface
   names are built-in macros, so a user definition named `run` shadows them.
3. **The scope check is dynamic, by liveness on the continuation**, not
   lexical. A lexical check is wrong: code built in a helper function and
   spliced back inside its binder's extent is legitimate (tested).
4. **Host frames do not hide liveness.** `*outer-k*` collects the
   continuations of machines suspended in host calls (`map`, `reduce`, …),
   so generators may use host higher-order functions. Found while writing
   example 2.
5. **Implicit cross-stage persistence = `lift`.** A present value used inside
   `code` is lifted with the same rules. Closures are lifted *as code* over
   their lifted captures (only the captures they mention). Self-referential
   closures and host functions become opaque constants (`:csp`, printed
   `#<csp …>`). A code value used at level 1 without `esc` is a stage error,
   not a lift.
6. **"Resource" (for `lift`'s refusal)** means atoms and other non-data host
   objects, records (handler instances, continuations), and genletrec
   generators, reachable from the lifted value. RFC 0001 authorities do not
   exist yet.
7. **A level-1 variable seen from level 0 is its code.** `(esc y)` under
   `fn [y]` means `(esc (code y))`. MetaOCaml rejects this statically, and
   T0 has no stage typing.
8. **Readable names without global state in the output.** `Gen` ids are
   global, and the printer renumbers per printed value (`x_1`, `t_2`, …).
   Binder names come from `:klara/names` metadata, which the expander
   attaches to core binder nodes. Metadata is excluded from `=` and from
   `code-id`, so CodeIds are unchanged (all S1 identity tests pass).
9. **genlet bindings and genletrec tables live in atoms in their frames.**
   A genlet from a nested machine must reach a locus in a suspended outer
   continuation, which cannot be rebuilt functionally.
10. **`recur` crosses `code`/`esc`.** `(code (recur ..))` built in a helper
    and spliced into a generated `loop` refers to that loop (example 6).
11. **REPL.** Definitions are published and their dependents invalidated at
    once (`;; stale: ..` lines). Every other form is expanded **once**: if it
    expands to a definition (`defn`), it is published; otherwise it is
    evaluated in a fiber on the session world. The guide branch's change made
    every expression expand twice, and S4 removed that. Printing: code as
    `(code <source>)`, closures `#<fn>`, throwables `#<Class "msg">`.
12. **Printer sugar.** `loop`/`recur` for loop-shaped letrecs, `do` for
    hidden binders, vectors as literals, host calls by their Clojure names.
    The loop sugar is off for `:expand`, which shows the core term.
13. **Transcript format.** `k=> form` lines, continuation lines indented ≥ 4
    spaces, expected output up to the next prompt, exact match, one session
    per file, `klara-repl :norun` for illustrative blocks.

## 3. Gaps and open questions

- **No formal semantics for staging.** `code`/`esc` are not in the ansatz
  spec. The informal claim (closed code satisfies `WS 0`, so `run` cannot
  reach `scope`) is not a theorem here. The natural next step is a two-level
  `Tm` with a liveness side condition on splice.
- **Multi-shot resumption inside a code bracket** shares the locus atoms, so
  both resumptions' bindings accumulate. Correct behaviour would copy loci
  on resumption, and needs the authority story of RFC 0001.
- **genlet floats past conditionals.** This matches BER, but it is only
  sound for pure expressions, and nothing checks purity.
- **No typed staging and no static level check for variables.** All errors
  are dynamic.
- **`lift` of closures loses the creation basis.** Lifted code resolves world
  names in the basis of whoever runs it. Opaque CSP constants make generated
  code non-serializable and give it identity-based CodeIds.
- **`run` interprets.** There is no compilation of generated code to host
  functions, no installation into the `klara.stage` cache, and no C back end
  (K3). The examples measure code size, not speed.
- **No syntax values.** `quote-syntax`, expansion-context capabilities and
  macros over code values (§6's syntax extensions) are not started.
- **`code-vector`** exists because code has no n-ary splice. A general
  `(code (f (esc-splice cs)))` form is an open design question.
- **Strymonas coverage.** `zip` and nested `flat_map` are not done
  (example 5).
- **Surface gaps found on the way.** `for` (needs `new`), `case` (needs
  `case*`), and forward references between top-level `def`s. The examples use
  `letfn` to work around the last one.
- **Interactive REPL** reads with the Clojure reader directly. It has no line
  editing, and a command's argument must follow on the same input.
