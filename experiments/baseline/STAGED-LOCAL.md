# Checked staged local-call preparation

2026-10-30. One warm-process diagnostic in the existing Oracle GraalVM 25 host
REPL. It compares identical 10,000-item score loops, with 2,000 warmup calls
per engine, nine rotating samples and 100 calls per sample. Results are checked
against `333283345000`; both compiled paths record hits with no fallback or
deoptimization. Cache hits count entry resolution, not every cached invocation.
This is not an independent-process or peak-performance claim.

| Variant | Median, µs/call | Current-thread bytes/call |
|---|---:|---:|
| Clojure | 4.44 | 26 |
| Existing optimizing compiler | 4.91 | 450 |
| Baseline with staged guest planner | 5.89 | 2,426 |

The guest path runs a pure planner generated by `code`/`esc` in
[`klara.local-optimizer`](../../examples/compat/klara/local_optimizer.cljc).
The planner traverses binding uses and proposes a local inline; the host
independently checks the selection and applies the fixed ordered rewrite.
The regular baseline emitter then handles the residual. No typed loop
variant, new special-case machine or profiler is used by this path.

Preparation observations in this already loaded process:

| Variant | Compile, ms | Validate/install, ms |
|---|---:|---:|
| Clojure | 3.27 | — |
| Existing optimizing | 5.48 | 1.42 |
| Guest staged baseline | 13.71 | 0.23 |

Guest module loading, including staged planner generation, took another
24.86 ms. The guest pass records 4,346 service transitions, 5,211 counted job
work units, one emission and 638 counted emitted-form bytes. These are not
exact class/heap sizes or timing bounds. Shared bootstrap/compiler code was
already loaded; do not read these observations as a cold startup distribution.
The existing optimizing path is not metered by this baseline job interface;
its empty usage map is not evidence of zero work.

The important outcome is that the same admitted program can now reach useful
native execution through a guest analysis, a checked recipe and the existing
before-use preparation API. T0 is unchanged. Preparation cost and the extra
baseline entry allocation remain opportunities for improvement. General
recipe/fact composition, adaptive investment and native metering of edited
compiler services remain open.

The [raw report](staged-local-results/repl-0.edn) contains the generated host
form, rule/source/residual receipts, compiler read provenance, samples and
source fingerprints. Its source cohort predates subsequent docstring-only
edits to `baseline.clj` and `staged.clj`; the exact measured versions are
retained under `staged-local-results/measured/`. `before/` instead preserves
the pre-pass sources needed by the earlier refinement cohorts.

Reproduce in the same host REPL without restarting it:

```clojure
(require '[baseline.staged-local :as experiment])
(experiment/run-study! "repl-new")
```

Or use a fresh JVM with `src` and `experiments` on the classpath:

```sh
clojure -J-Xmx1g -Sdeps '{:paths ["src" "experiments" "verification" "verification/proof_staging"]}' -M -m baseline.staged-local fresh
```

New output goes under `target/staged-local/`. See the
[implementation contract](../../doc/engineering/guest-local-calls.md) for
the checker, limits, staging example and remaining proof obligations.

After REPL iteration, clean standalone checks pass: **260 tests / 7,316
assertions** with `clojure -M:test`, and **141 tests / 3,490 assertions** with
`clojure -M:verify`. These test results do not establish the general semantic
theorem or statistical performance claims described as open above.
